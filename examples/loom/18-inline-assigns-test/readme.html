Lesson 18 — inline assigns

An inline assign lets you change a variable from inside a line of text. It surfaces as nothing in the rendered output — but the side effect runs. Useful for "this dialogue beat earns the player some trust" or "speaking this line lights the lantern".

The shape

Anywhere inside a text line, drop <...> with a mutation inside:

WREN
  Thank you for coming.<$bells_struck++>

The angle brackets are what say "this is an inline effect, not text". Today the inline form is reliably parsed for the $x++ shape (which takes no right-hand side). For richer changes — :=, +=, -= — use a regular ~ action line on the next line down: 

WREN
  She lights the lamp.
~ $lantern_lit := true
Parser note. The design specifies that inline <$x := value> works for any operator, but the current parser can confuse the closing > with the greater-than comparison when reading the RHS expression. A future parser fix will unlock the full form. For now, ~ action lines are the reliable way to set or adjust a value at a specific beat.

Multiple in one line

You can chain them:

WREN
  <$lantern_lit := true>The wick catches.<$bells_struck++>

The text reads as "The wick catches.", and behind the scenes two mutations fire.

Why not just use ~?

Inline assigns are for when the side effect belongs to the dialogue beat — the line and the change are the same moment in the story. Compare: 

WREN
  Thank you for coming.
~ $trust += 5

vs.

WREN
  Thank you for coming.<$trust += 5>

Mechanically identical. Stylistically the inline form makes the dependency obvious: this line is what raised her trust. Use whichever reads cleaner.

When the assign fires

Loom evaluates the line's text first (so any $x interpolation reads the old value), then applies the inline assigns. The same applies to ~ action lines that sit on the next line: the dialogue beat is rendered against the pre-change values, the action is applied right after, and the next beat reads the new value.

What you just learned

  • <$x := v> inside a text line is an inline assign.
  • Same operators as actions: :=, +=, -=, ++.
  • The mutation runs after the line is rendered, so subsequent beats see the new value.
  • Use inline assigns when the change belongs to the moment; use a standalone ~ action when the change stands on its own.
The angle brackets again. Loom uses < > for "an effect happens here" — inline assigns are the most common one. Cues and triggers reuse the same bracket family for the same reason: a side effect that doesn't render as visible text.
Try this. Open lesson.loom. Add an inline assign that decreases $trust on a colder line — for example <$trust -= 3>. Watch trust drop on subsequent beats.
