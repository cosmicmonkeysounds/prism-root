Lesson 19 — backlinks

A backlink is a soft cross-reference inside prose — "this line mentions the keeper, who is described elsewhere." Backlinks render as highlightable text in compatible editors, and the runtime preserves the reference so a codex / wiki view can spell-check links and surface related material.

The shape

[[target]]            ← display is the target verbatim
[[target|display]]    ← explicit display text

Inside a line:

WREN
  Ask [[maren|Maren]] about the bell when you find her.

That sentence renders as Ask Maren about the bell when you find her. The runtime keeps the backlink target (maren) so a hyperlink layer can route a click to her character page.

Backlink vs @ reference

Style Question If broken
@maren "Does Maren exist as a declared thing?" Build error.
[[maren]] "This prose mentions Maren." Warning at most — the show still plays.

The rule of thumb: use @id when the runtime needs to do something with the reference (route a cue to a target, look up a character profile). Use [[id]] when the reference is audience-facing prose.

Where backlinks shine

  • Codex entries — every [[bell_of_tides]] mention can backlink to the article.
  • Drafts — the writer can sketch a reference now and define the target later without breaking the build.
  • Hyperlinked playback — a host UI can render backlinks as clickable spans.

What you just learned

  • [[target]] is a backlink with display text matching the target.
  • [[target|display]] sets explicit display text.
  • Backlinks are intentionally soft — a missing target warns, never breaks.
One last bracket. Loom has eight bracket / sigil families — $, @, [[ ]], < >, [ ], ( ), { }, ''' '''. Five of them you've now met. The remaining three ([ ] text variations, ( ) computations, ''' ''' docstrings) are introduced as needed by future lessons.
Try this. Open lesson.loom. Add a backlink to a fictional location — [[harbor|the harbor]] — in any flavor line. The runtime doesn't care that harbor isn't declared anywhere.
