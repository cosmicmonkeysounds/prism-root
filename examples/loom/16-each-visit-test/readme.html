Lesson 16 — each visit

A common writing pattern: the first time the player visits this scene one thing happens, the second time another, after that nothing surprising any more. Loom has a dedicated block for it.

The shape

each visit
  first
    WREN
      Morning. New face.
  then
    WREN
      Back again.
  finally
    WREN
      You're practically furniture now.

The three branch labels:

  • first — plays on visit number one.
  • then — plays on every visit after the first, until finally takes over.
  • finally — plays from the visit after all the then branches are exhausted onwards.

Multiple then branches

You can write several then branches in a row to cycle through them:

each visit
  first
    WREN
      Welcome.
  then
    WREN
      Back so soon?
  then
    WREN
      Make yourself at home.
  finally
    WREN
      Tea's on.

Reading top-to-bottom: visit 1 fires first, visit 2 fires the first then, visit 3 fires the second then, visit 4 onwards fires finally.

Without finally

If you leave finally off, the last then branch keeps playing forever after its first appearance. Useful when you want a graceful settle into a stable line.

Without first

You can leave first off too. Then visit one fires the first then and so on.

What this replaces

Before each visit existed, the same effect required:

~ var $visit_count := 0
~ $visit_count++

after $visit_count == 1
  WREN
    Welcome.
after $visit_count == 2
  WREN
    Back again.
after $visit_count >= 3
  WREN
    Furniture.

It works — but the intent ("evolve the line over repeated visits") is buried in arithmetic. each visit says it out loud.

What you just learned

  • each visit opens a visit-evolving block.
  • first plays on visit one; then plays on each subsequent visit (cycle if there are multiple); finally settles onto the closing line.
  • Each branch can contain any content — dialogue, flavor, mutations, even more blocks.
What counts as a visit. Every entry to the section bumps the visit count by one — whether you fell through, diverted into it, or returned. The ledger is what tracks the count, so it survives save / load and is consistent with visits(section_id) reads.
