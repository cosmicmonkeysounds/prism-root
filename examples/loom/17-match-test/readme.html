Lesson 17 — match

after is a two-way fork. match is a many-way fork. Hand it a value and a set of possible values, and it picks the block that matches.

The shape

match $weather
  storm
    WREN
      Stay inside.
  fog
    WREN
      Walk slow.
  clear
    WREN
      Good day for it.
  _
    WREN
      I have no opinion on the weather.

Reading it:

  • match $weather — the value to inspect.
  • Each arm is a possible value followed by an indented body.
  • _ is the catch-all — it matches anything none of the other arms caught.

The runtime evaluates $weather, finds the first arm whose discriminant matches, and plays its body. The other arms don't run.

What arms can match

  • A bare identifier: storm, fog, clear.
  • A quoted string: "north_road".
  • A number: 3.
  • An underscore (_) for the catch-all.

The comparison is straightforward equality — Loom turns the matched value into a string and compares to the arm head.

When to reach for match

Shape Use
Two outcomes, both common after / otherwise
3+ named outcomes match
"Did this ever happen?" yes/no guarded section or choice

What you just learned

  • match <expression> picks one of many indented arms.
  • Each arm starts with the value to compare (identifier, string, number, or _).
  • The catch-all _ is good hygiene — it stops the playhead from silently doing nothing when a new value sneaks in.
