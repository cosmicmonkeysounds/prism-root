Lesson 10 — putting variables in dialogue

Variables become visible to the audience the moment you put them inside a line of dialogue. Loom calls this interpolation: the runtime substitutes the variable's current value into the rendered text at the moment the line is spoken.

The simple form

Drop a $name straight into a line:

~ var $trust := 30

WREN
  Trust meter: $trust.

When that plays the player sees Trust meter: 30.

If $trust changes later, the next time the line plays it shows the new value. There's no caching — every render reads the current value.

The braced form

When you need to interpolate something more elaborate than a bare name — an expression, or a value that sits inside another structure — wrap it in ${...}: 

WREN
  In total, you've earned ${$trust + 5} points of trust.

The braced form is also clearer when the variable's name runs straight up against other characters (e.g. ${name}_id vs the ambiguous $name_id).

Mixing prose and variables

Both forms compose freely with regular text and with each other:

WREN
  Welcome to $town. The bell has struck $bells_struck times.

WREN { soft }
  Trust ${$trust} out of one hundred. We'll get there.

What if the variable doesn't exist?

If you reference a variable that hasn't been set, Loom renders it as nil. That's a visual signal during development — if you see the word "nil" appear in dialogue, the line ran before whatever was supposed to set the value.

What you just learned

  • $name inside a dialogue line is replaced with the current value when the line plays.
  • ${...} is the braced form, useful for expressions or disambiguation.
  • Re-running the same line later will show the new value — there's no snapshot.
  • Unset variables render as nil.
Try this. In lesson.loom, add a third section that bumps $trust with ~ $trust += 20 and then re-plays the same "Trust meter: $trust" line. You'll see the same line print a different number on its second visit.
