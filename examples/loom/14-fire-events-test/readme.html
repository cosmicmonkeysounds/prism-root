Lesson 14 — events

Sections and choices are structural things the ledger remembers automatically. An event is your hook for anything that doesn't fit those — "the bell rang", "a deal was struck", "the sun rose". You fire one with ~ fire name and check it later with the same ledger queries.

Firing

An action line at the moment the thing happens:

~ fire bell_rang
~ fire deal_struck
~ fire sun_rose

Each fire writes an entry into the ledger stamped with the current time. The name is yours to choose; convention is lowercase with underscores.

Asking "did this happen?"

Two reads cover most cases:

Query Returns
since(name) Milliseconds since the event last fired, or nothing if it never has.
count(event) Total number of events fired so far. Useful as a rough heartbeat.

Putting them in conditions:

* Strike it again.  if since(bell_rang) > 5000

after since(deal_struck) < 30000
  WREN
    We just shook on this.
Guards live on sections and choices. To gate a single dialogue beat, wrap it in after <cond> (see lesson 15).

The numbers are in milliseconds, so 5000 is five seconds.

The full pattern

  1. Something happens in the story → ~ fire X.
  2. Later, a line wants to react → if since(X) < N or similar.
  3. The ledger handles the bookkeeping.

Events vs choices in the ledger

Both end up in the same ledger. The difference is just that chose(...) looks at choice entries and since(...) / count(event) look at fired event entries. Same diary, different views.

What you just learned

  • ~ fire name records a custom event.
  • since(name) returns time-since in milliseconds (or nothing).
  • count(event) is the total number of events fired.
  • Use events for one-off "the thing happened" moments — variables for things with a level, the ledger for things with a history.
Where does "now" come from? The runtime carries a virtual clock. The host advances it (typically tied to wall-clock seconds, but it can be anything monotonic — frame counts, tide cycles, beats). Saves preserve the clock so reloads come back at the right "now".
Try this. In lesson.loom, fire a second_strike event and add a line that prints only if since(second_strike) < 1000. The line will play because the second strike just happened.
