Lesson 09 — variables

A variable is a labeled box where the story keeps a value. "Wren's trust in the player is 30." "The bell has been struck twice." "The lantern is lit." Variables let the story remember things between scenes — and lessons 10–12 will let dialogue and choices react to them.

The shape

To create or change a variable, write an action line:

~ var $trust := 30

Reading it left to right:

  • ~ says "this line is an action — do something, don't say something".
  • var is the action keyword. It introduces a variable.
  • $trust is the variable's name. Variables always wear a $ prefix.
  • := means "set to" (note: a colon before the equals; not just =).
  • 30 is the value.

Types of value

Variables can hold:

  • Whole numbers: ~ var $trust := 30
  • Fractions: ~ var $progress := 0.5
  • True or false: ~ var $met_wren := true
  • Text: ~ var $town := "Saltmere"

Three operators, three meanings

One thing about Loom that catches new writers: three operators look similar but mean different things.

Operator Meaning Where
:="set this to that"actions, mutations
=="is this equal to that?"conditions (next lesson)
="this is that" (bind, declare)let, properties

When in doubt: := changes a value, == compares, = declares.

Updating without re-declaring

Once a variable exists, you don't need var anymore:

~ var $trust := 30      # introduce it
~ $trust := 50          # raise it
~ $trust += 10          # add ten
~ $trust -= 5           # take five away
~ $trust++              # add one

These are the four mutation shapes. := overwrites, += adds, -= subtracts, ++ bumps by one.

Firing events

A close cousin of ~ var: ~ fire. It records that something happened.

~ fire bell_rang

Events go into the ledger so later lines can ask "how long since the bell rang?" — but that's a lesson 14 topic. For now, just know that events and variables travel together.

What you just learned

  • ~ opens an action line.
  • ~ var $x := value creates a variable.
  • $x := v, $x += v, $x -= v, $x++ are the four mutation shapes.
  • ~ fire event_name records that an event happened.
  • := sets, == compares, = declares — don't mix them.
Where do variables live? The runtime keeps them in a single per-show map. Saves serialize that map, so a player who quits and reloads comes back with every $trust intact.
Try this. Add a ~ var $bells_struck := 0 at the top of a section in lesson.loom, and then bump it with ~ $bells_struck++ after a flavor line. You won't see the count yet — that needs interpolation, the very next lesson.
